Prod-run spike for adding **SST + SST anomaly** to the viewer as a standalone daily

## 1. Source decision (research 2026-08-06)

| Role | Source | Why |
|---|---|---|
| **Absolute SST (primary)** | NOAA/NESDIS **Geo-Polar Blended 5km** (0.05°, daily, <24h latency) | Best resolution/latency/reliability tradeoff with raw-grid access |
| **SST anomaly (primary)** | NOAA Coral Reef Watch **5km daily SST anomaly** (`noaacrwsstanomalyDaily` lineage, 1985–present) | NOAA's own matched-climatology anomaly on the Geo-Polar family — no home-built climatology, no cross-dataset bias artifact |
| **Fallback** | **OISST v2.1** (0.25°, open AWS bucket, `anom` in-file) | Most bulletproof feed; too coarse to be primary (blurry at NA 9km) |
| **Rejected** | NASA GIBS / MUR | GIBS = pre-rendered tiles only (no hover values, no custom ramps/legends/units). MUR = ~700 MB/day + Earthdata auth; AWS zarr mirror frozen at 2020 |

The plan doc's warning about mixing Geo-Polar SST with an OISST climatology stands —
we avoid it entirely by consuming NOAA's pre-paired anomaly product instead of
deriving anomalies ourselves.

**Units decision: °C only.** Effectively every SST product is °C (or Kelvin
trivially converted). No °F support anywhere in the SST path — packing, sampling,
legend, and display are all °C. (`sst`: uint16, scale 0.01 °C, offset −5;
`sst_anom`: uint16, scale 0.01 °C, offset −30.)

Open question the spike answers: the CRW anomaly is night-lineage. The spike fetches
both Geo-Polar variants (day+night, night-only) and reports mean/max |ΔSST| so we can
decide whether DN absolute SST can sit next to the night-lineage anomaly.

## 2. What spike v2 measures (on prod, apples-to-apples)

`backend/scripts/measure_sst_sizing.py` (v2) — extends the v1 script; all v1 safety
guards intact (refuses root, refuses any write path inside `/opt/cartosky/data` or
`/opt/cartosky/herbie_cache_ssd`, everything under `{dev_root}/sst/`).

1. **Fetch-path reliability from prod's network**: per-URL probe log for
   CoastWatch ERDDAP (griddap), NCEI GHRSST archive, CoastWatch THREDDS, NOAA STAR
   archive (CRW), OISST NCEI. Gotchas already baked in: ERDDAP 403s the default
   `python-requests` User-Agent (script sends `CartoSky-SST-Sizing/1.0`); the two
   Geo-Polar ERDDAP variants disagree on units (DN=°C, night=Kelvin) so units are
   auto-detected from netCDF metadata.
2. **Conversion through the real production writer** (`write_grid_frame_for_run_root`,
   4326 path mirrors `fastpath/subloop.py`) onto the **real target grids**, derived
   from `get_target_grid` and hard-asserted against `sources/openmeteo/grids.py`:
   - NA: EPSG:3857, 9 km, 1825×1893
   - Global: EPSG:4326, 0.25°, 721×1440
3. **Prod storage projection**: measured per-day artifact bytes
   (bin + meta + json + gz/br sidecars) for {sst, sst_anom} × {na, global},
   projected over 7/30/90/365-day retention windows. Raw `.nc` downloads reported
   separately as transient. (Reference points from the local smoke run,
   CRW anomaly 2026-08-03: raw 197.8 MiB via ERDDAP float64 vs **10.7 MiB** for the
   same data from the STAR archive; converted na 9.40 MiB, global 3.19 MiB.)
4. **Eyeball PNGs** per candidate × grid → `{dev_root}/sst/reports/png/`
   (SST −2..35 °C ramp; anomaly ±5 °C diverging; land/NaN transparent).
5. **DN↔night pairing stat** (item 1 in §1's open question).

## 3. Prod run instructions

```bash
# 1. Pull the commit into the dev checkout on the prod box
cd /opt/cartosky-dev && sudo -u cartosky git pull && git log --oneline -1
```

```bash
# 2. Run the spike: as cartosky, resource-wrapped, confined to /opt/cartosky-dev/sst/
sudo systemd-run --scope --uid=cartosky --gid=cartosky \
  -p MemoryHigh=4G -p MemoryMax=6G -p CPUWeight=50 -p IOWeight=50 \
  nice -n 10 ionice -c 2 -n 7 \
  /opt/cartosky-dev/.venv/bin/python \
  /opt/cartosky-dev/backend/scripts/measure_sst_sizing.py --verbose
```

Notes:
- Default `--dev-root` is `/opt/cartosky-dev`; default `--candidate all` runs
  oisst + geopolar (both variants) + crw_anom. Expect roughly 0.5–1 GB of transient
  downloads (ERDDAP serves float64), deleted at the end; reports + PNGs persist.
- Add `--keep` to retain downloads/converted artifacts for inspection.
- Add `--date YYYYMMDD` to pin a day (else auto walk-back from today−2).
- Exit 0 requires geopolar to be measured; per-path misses are recorded findings.

```bash
# 3. Collect results
cat /opt/cartosky-dev/sst/reports/sst_sizing_*.json | less   # or just paste the printed summary
ls -la /opt/cartosky-dev/sst/reports/png/
```

Paste the printed summary block back into chat; pull the PNGs to the Mac for the
looks-nice check:

```bash
scp 'PROD:/opt/cartosky-dev/sst/reports/png/*.png' ~/Desktop/sst-spike/
```

## 4. Follow-on plan (post-spike, for reference)

- Phase 1 — absolute `sst`: standalone daily obs plugin modeled on MRMS
  (`product="obs"`, `time_axis_mode="observed"`), ERDDAP-primary/archive-fallback
  fetch, NA + global grids, sequential ramp, °C only.
- Phase 2 — `sst_anom`: fetched from the CRW anomaly product (no derive step,
  no climatology build), diverging ±5 °C ramp.
- Later: higher-res global SST grid (0.25° global downsamples the 5 km data; NA
  keeps the benefit), OISST automated failover, historical archive scrubbing.
